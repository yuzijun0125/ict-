# 📌 一页看懂

| 你可能想问 | 回答 |
|---|---|
| **做什么？** | 一个帮医生看眼底照片的 AI 助手 |
| **怎么用？** | 医生上传患者眼底照片 → AI 说出"看到了什么、可能是什么、依据是什么" → 医生确认或修改 |
| **帮谁解决什么？** | 帮医生（尤其基层医生）少漏诊、看得快、判断更一致 |
| **凭什么叫"可进化"？** | 医生每次的修改都会被记下来，下次遇到类似的片子，判断更接近这位医生的标准 |
| **绝对不做什么？** | 不下诊断结论、不开药、不替代医生 |

**一句话总结**：
> 做一个"会看片子、有记性、越用越准"的助手，但**最终拍板的一定是医生**。

# 一、我们要做的是什么

## 1.1 用一句话说清楚

**给医生一个能看懂眼底照片的 AI 助手。**

它看完片子后，会告诉医生三件事：

1. **我看到了什么** —— 客观描述（比如"右眼后极部有散在点片状出血"）
2. **我猜可能是什么** —— 给出几种可能性，并有先后排序
3. **我的依据是什么** —— 引用教科书、指南的哪一条

然后由医生判断：**说得对，采纳**；**说得不对，改掉**。

## 1.2 一个具体例子（看完就懂了）

> **场景**：社区医院的李医生，刚给一位糖尿病 10 年的患者拍了眼底照片。
> 李医生不是眼科专科医生，看着照片上的出血点不太确定严不严重。

**没有我们的系统时**：
李医生只能写"眼底可见出血，建议转诊上级医院"，或者干脆漏掉早期病变。

**有了我们的系统时**：

```
【AI 助手输出】

🖼 影像质量：可判读（清晰度良好）

👁 影像所见
  · 视网膜：双眼后极部散在点状、片状出血，分布于 4 个象限
  · 微动脉瘤：颞侧可见多个（约 8～10 个）
  · 渗出：黄斑区硬性渗出，呈环形分布
  · 静脉：可见静脉扩张，局部呈串珠样改变
  · 视盘：边界清晰，杯盘比约 0.4

🔍 可能的诊断方向（按可能性排序）
  1. 糖尿病视网膜病变（重度非增殖期，建议 ICDR 分级确认）
     支持依据：4 象限出血 + 静脉串珠样改变 → 符合重度 NPDR 的"4-2-1"标准
     依据来源：《我国糖尿病视网膜病变临床诊疗指南（2022年）》
  2. 糖尿病黄斑水肿（需 OCT 进一步确认）
     支持依据：黄斑区硬性渗出环形分布
  3. 需鉴别：视网膜静脉阻塞
     鉴别要点：RVO 多为单眼、出血沿血管分布更明显

⚠️ 免责声明：以上为辅助意见，仅供参考，不构成诊断结论。
   请结合患者病史、体征及进一步检查，由执业医师作出诊断。
```

**Then**：
李医生看到"4-2-1 标准"和指南出处，核对了照片，认同了这个判断 → 点「**采纳**」。
（如果他觉得不准确，就点「**修正**」，选正确的分级，写一句原因。）

> 📖 **术语注解**（对应上面示例里出现的缩写）
>
> | 缩写 | 英文全称 | 中文 | 一句话解释 |
> |---|---|---|---|
> | **DR** | Diabetic Retinopathy | 糖尿病视网膜病变 | 糖尿病损伤眼底微血管引起的病变，工作年龄人群致盲首因 |
> | **NPDR / PDR** | Non-Proliferative / Proliferative DR | 非增殖期 / 增殖期 | 同一疾病 DR 的早中期 / 晚期；晚期会长出易出血的新生血管 |
> | **ICDR** | International Clinical DR severity scale | 国际临床 DR 严重程度分级 | **全球通用的 DR 分级标准**（无明显/轻度/中度/重度 NPDR/PDR） |
> | **4-2-1 标准** | — | 重度 NPDR 判定规则 | 4 象限出血、2 象限静脉串珠、1 象限 IRMA，**满足任一即为重度** |
> | **IRMA** | Intraretinal Microvascular Abnormalities | 视网膜内微血管异常 | 提示视网膜缺血的血管异常，是 4-2-1 中的一条 |
> | **DME** | Diabetic Macular Edema | 糖尿病黄斑水肿 | 黄斑区渗漏肿胀，是糖尿病眼病视力下降的主因 |
> | **OCT** | Optical Coherence Tomography | 光学相干断层扫描 | 能"切面"看视网膜各层，是判断黄斑水肿的金标准 |
> | **RVO** | Retinal Vein Occlusion | 视网膜静脉阻塞 | 眼底静脉被血栓堵住，可理解为"**眼底中风**" |
> | **CFP** | Color Fundus Photography | 彩色眼底照相 | **本项目的主要输入**——眼底相机拍的照片 |

**关键点**：
- AI 说的是"**可能的诊断方向**"，不是"确诊"
- AI 给了"**依据**"，李医生可以自己核对，而不是盲信
- 最后的判断是李医生做的

## 1.3 它和普通 AI 聊天有什么不一样

| | 普通 AI 聊天 | 我们的助手 |
|---|---|---|
| 输入 | 文字 | **眼底照片** + 临床信息 |
| 输出 | 一段话 | **结构化的所见 + 排序 + 依据** |
| 依据 | 说不清 | **每条都指到具体指南** |
| 会不会变聪明 | 不会 | **医生改一次，它就记一次** |
| 谁负责 | 不清楚 | **医生，白纸黑字写在界面上** |

# 二、为什么做这个

## 2.1 医生面临的真实困难

| 困难 | 具体表现 |
|---|---|
| **不会看** | 基层医生、非眼科医生看眼底片，早期病变容易漏掉 |
| **没人看** | 眼科专家集中在大医院，基层"拍了片没人读" |
| **看法不一** | 同一张片子，不同医生判断的分级可能不一样 |
| **太耗时** | 一张片子仔细读要几分钟，体检/筛查量大时跟不上 |
| **经验留不下** | 老医生的判断经验在脑子里，带不走、传不下去 |

## 2.2 为什么选择"辅助诊断"而不是"AI 自己诊断"

这是整个项目最重要的一条边界：

| | AI 自己诊断 | **我们做的：辅助诊断** |
|---|---|---|
| 合规 | 属于医疗器械，需要国家审批注册 | 定位为辅助工具，科研与演示可用 |
| 责任 | 出了问题谁负责？说不清 | 医生负责，AI 只提供参考 |
| 反馈 | 没有反馈来源，无法进化 | **医生的修改就是最好的反馈** |
| 可行性 | 极高门槛 | 学生在竞赛周期内可以做完、做好 |

**一句话**："AI 自己诊断"走不通，但"AI 帮医生看得更快更准，并且从医生那里学习"——**既能落地，又正好对上赛题要求的"可进化"**。

# 三、系统怎么运转

## 3.1 一张图看懂全流程

```
                     ┌─────────────────────┐
                     │   医生（最终拍板）    │
                     └──────────▲──────────┘
                                │ 采纳 / 修改
  患者眼底照片 ──┐              │
                ├──►  AI 助手 ──┘
   患者临床信息 ──┘      │
                         ├─ ① 先看照片清不清楚（不清楚就提示重拍）
                         ├─ ② 描述看到了什么
                         ├─ ③ 列出几种可能，并排序
                         ├─ ④ 给出依据（引用指南）
                         └─ ⑤ 附免责声明
                                │
                                ▼
                    医生改过的结果 → 记下来 → 下次更准
```

## 3.2 AI 助手每一步在做什么

| 步骤 | 做什么 | 为什么这么做 |
|---|---|---|
| ① 影像质控 | 判断照片能不能看清 | 看不清的照片强行分析，只会出错 |
| ② 征象描述 | 只描述"看到什么"，不下结论 | 让医生能核对，也避免 AI 越权 |
| ③ 可能性排序 | 列出 1～3 种可能，排好序 | 给医生参考，而不是给唯一答案 |
| ④ 给依据 | 说明"为什么这么判断"，引用指南 | 医生可以验证，不是黑箱 |
| ⑤ 免责声明 | 明确"这只是参考" | 合规底线 |

## 3.3 "可进化"是怎么实现的（重点）

**打个比方**：
> 就像带一个住院医师。第一次他看错了，老师纠正他；第二次遇到类似的片子，他就记住了。看得越多、被纠正得越多，他越接近老师的水平。

**具体流程**：

```
第 1 次：
  AI 说："中度非增殖期"
  医生说："不对，是重度"  ← 修正

第 2 次遇到类似片子：
  AI 记住了上次的教训 → 说："重度非增殖期（参考既往相似病例）"

积累一段时间后：
  AI 的判断越来越接近这位医生的标准
  医生需要修改的次数越来越少  ← 这就是"进化"的证据
```

**"进化"用什么证明？**（评委一定会问）

| 证据类型 | 具体怎么展示 |
|---|---|
| **行为证据** | 同一张片子，反馈之后再问，结论更接近医生的判断 |
| **数据证据** | 准确率、一致性（Kappa）从 v1 到 v2 提升 |
| **过程证据** | 记忆条目在增长、规则在更新、版本在迭代 |

# 四、具体有哪些功能

| 编号 | 功能 | 通俗说明 |
|---|---|---|
| F1 | **影像质控** | 先看照片清不清楚，不清楚就提醒重拍 |
| F2 | **征象描述** | 说出照片上看到了什么（出血、渗出、新生血管……） |
| F3 | **可能性排序** | 列出可能是哪些病，按可能性排序 |
| F4 | **分级建议** | 给出糖尿病视网膜病变等的严重程度分级 |
| F5 | **复查/转诊建议** | 建议多久复查、要不要转上级医院 |
| F6 | **医生反馈** | 医生点"采纳 / 修改 / 否决"，并可写原因 |
| F7 | **给出依据** | 每条判断都能追到具体的影像所见和指南条文 |
| F8 | **安全护栏** | 自动拦掉"确诊""开药"这类越界说法 |
| F9 | **进化看板** | 用图表展示：改得越来越少了、越来越准了 |

其中 **F2（看得准）、F3（排序合理）、F6（能反馈）** 是核心。

# 五、技术方案

## 5.1 系统由哪几块组成

| 模块 | 作用 | 通俗理解 |
|---|---|---|
| **看图模块** | 把照片变成"文字描述" | 相当于 AI 的"眼睛" |
| **知识模块** | 存着指南、诊断标准、典型病例 | 相当于 AI 的"教科书" |
| **推理模块** | 综合"看到的 + 教科书"得出结论 | 相当于 AI 的"大脑" |
| **记忆模块** | 记住医生的每次修改 | 相当于 AI 的"经验" |
| **评估模块** | 算准确率、看进步了多少 | 相当于"考试" |
| **界面模块** | 医生上传照片、看结果、点采纳 | 医生实际操作的地方 |

## 5.2 关键技术（简单说明）

| 技术 | 用在哪儿 | 说明 |
|---|---|---|
| **多模态大模型（VLM，Vision-Language Model，视觉语言模型）** | 看图 | 能同时理解图片和文字，让 AI"描述照片" |
| **知识库检索（RAG，Retrieval-Augmented Generation，检索增强生成）** | 查依据 | 从指南里找到对应条款，作为判断依据 |
| **记忆机制** | 记住经验 | 把医生的修改存起来，下次调用 |
| **安全护栏** | 合规 | 用规则拦截越界表述 |
| **评测指标** | 证明效果 | 用准确率、一致性等指标证明"真的变好了" |

## 5.3 用什么工具做

| 环节 | 选择 |
|---|---|
| 智能体平台 | **ModelEngine / Nexent**（赛题指定，自带知识库、记忆、护栏） |
| 大模型 | DeepSeek / Qwen 等（中文医学场景表现好） |
| 视觉模型 | Qwen-VL 等（负责看懂眼底照片） |
| 向量模型 | BGE-M3 等（把文字转成向量，用于知识库的语义检索） |
| 影像处理 | OpenCV / PyTorch（照片清晰度检测、区域定位） |

# 六、能带来什么价值

## 6.1 对医生

- **看得更快**：AI 先出一份"初步意见"，医生只需要核对和修改
- **看得更准**：微小病变（微动脉瘤等）不容易漏
- **判断更一致**：大家用同一套口径，不同医生结论差异变小

## 6.2 对患者

- 早发现早治疗，减少可避免的失明
- 不必为了看一张片子跑到大医院

## 6.3 对医院和基层

- 优质眼科判断能力"下沉"到基层
- 老医生的经验可以沉淀下来，帮助年轻医生

## 6.4 怎么量化（用来写报告）

| 指标 | 意思 |
|---|---|
| 敏感度 | 有病的能不能查出来（少漏诊） |
| 特异度 | 没病的会不会被误判（少误诊） |
| Kappa 一致性 | 和医生的判断有多一致（0～1，越大越一致） |
| 修改率 | 医生要改的比例（越用越低 = 进化） |
| 单例耗时 | 看一张片子要多久 |

# 九、风险与底线

| 风险 | 怎么防 |
|---|---|
| 被认为在"做诊断" | 全程用"考虑/疑似/建议"措辞，界面写明免责声明，明确医生拍板 |
| 照片质量差导致误判 | 先做质控，不清楚就要求重拍，不硬分析 |
| 数据隐私 | 用公开数据集；真实数据必须脱敏 + 伦理审查 |
| 医生懒得反馈 | 反馈设计成"一键采纳/修改"，尽量省事 |
| 被质疑"进化是假的" | 用行为 + 数据 + 过程三类证据一起证明 |

## 三条不能破的底线

1. **只给辅助意见，不下最终诊断**
2. **必须给出依据**（可追溯、可核对）
3. **医生必须在环**（最终判断永远是医生做）
