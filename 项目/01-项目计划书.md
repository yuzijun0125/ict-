## 版本说明

本版将项目重新定位为**纯西医眼底影像辅助诊断**，不设置非西医诊疗模块。系统以眼底影像分析为核心，以病历、检验和随访信息为约束，以完整、可追溯的西医眼科知识库为推理依据，并支持医生针对当前病例连续提问。所有输出均为供医生复核的辅助意见。

> “完整知识库”在本项目中指：在已承诺的疾病与模态范围内，来源、维度、术语、更新、评测和安全规则完整，并非宣称覆盖全部医学知识。

## 0. 项目定位（重要）

### 0.1 一句话定位

**把眼底影像、病历、检验和既往随访资料组织成一条可追溯的证据链，输出“看到了什么、可能是什么、为什么这样判断、还缺什么”，最终由医生做诊断。**

系统不仅要分析一张图片，还要回答病例层面的问题：病灶与患者病史是否一致、检验结果是否支持当前假设、既往影像是否提示进展、相似疾病如何鉴别，以及医生追问的每条依据来自哪里。

### 0.2 产品形态

```
        ┌─────────────────────────────────────────┐
        │           医生（最终决策者）              │
        └───────────────▲─────────────────────────┘
                        │ 复核 / 确认 / 修正
        ┌───────────────┴─────────────────────────┐
患者眼底影像 ──►│    Nexent 眼底辅助诊断智能体            │
（CFP/OCT/OCTA）│  ① 影像质控   ② 征象描述               │
       +        │  ③ 疑似疾病排序  ④ 分级建议             │
   临床信息      │  ⑤ 判断依据（可溯源）  ⑥ 免责声明        │
                └─────────────────────────────────────────┘
                        │
                        ▼
              医生修正结果 → 反馈沉淀 → 智能体进化
```

### 0.3 三条铁律（合规与可信基础）

1. **只给"辅助意见"，不下"最终诊断"** —— 输出为"疑似/考虑/建议结合临床"，最终诊断由执业医师作出
2. **必须给依据** —— 每条意见附征象依据与指南出处，可溯源、可复核
3. **医生必须在环** —— 医生确认/修正的结果是系统唯一的"金标准"，也是进化的唯一反馈源

> **合规说明**：本项目定位为**科研与竞赛演示用辅助诊断工具**，非医疗器械，不用于临床独立诊断，未经 NMPA 注册不得用于临床诊疗决策。产品界面与文档均展示免责声明。

## 1. 项目背景与痛点

### 1.1 疾病背景

眼底疾病是我国主要的不可逆致盲原因，**早期可无症状、晚期不可逆、早期发现可显著降低致盲率**。

| 疾病 | 典型影像征象 | 临床意义 |
|---|---|---|
| 糖尿病视网膜病变（DR） | 微动脉瘤、点片状出血、硬性渗出、棉絮斑、静脉串珠、IRMA、新生血管、玻璃体积血 | 糖尿病患者主要致盲原因 |
| 糖尿病黄斑水肿（DME） | 黄斑区增厚、囊样水肿、硬性渗出环 | 视力损害主因 |
| 年龄相关性黄斑变性（AMD） | 玻璃膜疣、色素改变、地图样萎缩、视网膜下出血、CNV | 老年致盲主因 |
| 视网膜静脉阻塞（RVO） | 视网膜出血沿血管分布、静脉扩张迂曲、棉絮斑、视盘水肿 | 突发视力下降 |
| 青光眼性视神经损害 | 视盘杯盘比扩大、盘沿变窄、RNFL 缺损 | 不可逆，需长期随访 |
| 病理性近视眼底病变 | 豹纹状眼底、脉络膜萎缩、漆裂纹、CNV | 年轻化趋势 |
| 视网膜脱离 | 视网膜隆起、裂孔、卷曲 | 眼科急症 |

### 1.2 医生侧的四个真实痛点

1. **读片能力分布不均** —— 基层医生、非眼底专科医生对早期征象敏感度低，漏诊率高
2. **专家资源稀缺** —— 眼底专科医师集中在三甲医院，基层"拍了片没人看"
3. **诊断一致性差** —— 不同医生对同一张片子的分级判断存在差异（观察者间一致性低）
4. **读片耗时** —— 单张眼底片判读需数分钟，大量筛查场景下效率不足

### 1.3 为什么选"辅助诊断"而不是"自主诊断"

| 维度 | 自主诊断 | 辅助诊断（本项目） |
|---|---|---|
| 合规 | 属医疗器械，需注册审批 | 辅助工具定位，科研/演示可用 |
| 责任 | AI 承担诊断责任（不可行） | 医生承担最终诊断责任 |
| 反馈 | 无明确反馈源 | **医生修正即反馈** ← 支撑"可进化" |
| 赛题契合 | 偏识别能力 | 正对"决策 + 可进化" |

## 2. 项目目标与范围

### 2.1 总目标

构建一个以眼底影像为输入、**辅助医生诊断**并具备**医生反馈驱动进化能力**的智能体，使诊断辅助的准确性与一致性随使用不断提升。

### 2.2 分目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 影像质控 | 自动判断影像是否可判读，不可判读时提示重拍 |
| G2 | 征象识别与描述 | 输出结构化征象（位置、类型、范围），**仅描述，不下结论** |
| G3 | 辅助诊断建议 | 输出疑似疾病及可能性排序，附征象依据与指南出处 |
| G4 | 分级建议 | 按 ICDR 等标准给出 DR 分级、AMD 分期等建议 |
| G5 | 可解释输出 | 每条建议可溯源到征象与指南条款 |
| G6 | 反馈与进化 | 医生确认/修正 → 记忆沉淀 → 知识库修正 → 版本迭代 |
| G7 | 安全护栏 | 拦截越界表述（确诊式断言、用药建议） |
| G8 | 病历综合分析 | 解析病历、检查报告、检验和随访时间线，识别缺项与冲突 |
| G9 | 医生连续问答 | 围绕当前病例回答解释、鉴别、缺项、纵向变化和证据来源 |
| G10 | 完整知识库 | 在西医眼科范围内覆盖疾病、影像、病历、检验、诊断、鉴别、急症和安全规则 |

### 2.3 范围边界

| 本项目做 | 本项目不做 |
|---|---|
| 影像征象描述 | 签发诊断报告 |
| 疑似疾病排序与依据 | 下最终诊断结论 |
| 分级/分期建议 | 治疗方案制定 |
| 复查/转诊建议（延伸） | 用药与剂量建议 |
| 影像质量评估 | 手术指征判定 |

## 3. 功能设计

### F1 影像接入与质控

- **输入**：眼底彩色照相（CFP）；可选 OCT / OCTA / 超广角
- **质控项**：清晰度、曝光、伪影、遮挡、视野完整性、单眼/双眼识别
- **输出**：`可判读` / `不可判读（原因）` → 不可判读直接建议重拍，**不进入诊断流程**（避免脏数据污染决策）

### F2 结构化征象描述（核心）

输出**不带结论**的客观描述，例如：

| 征象类别 | 输出示例 |
|---|---|
| 出血 | 右眼后极部散在点片状出血，约 4 个象限 |
| 微动脉瘤 | 颞侧可见多个微动脉瘤 |
| 渗出 | 黄斑区硬性渗出，呈环形分布 |
| 棉絮斑 | 上方血管弓附近可见棉絮斑 |
| 新生血管 | 视盘周围可见新生血管（需医生确认） |
| 视盘 | 杯盘比约 0.6，盘沿形态待评估 |
| 黄斑 | 中心凹反光欠清，可疑黄斑水肿 |

> 设计原则：**描述与推断分离**，为医生复核提供可核对的客观图层。

### F3 辅助诊断建议

- 输出**疑似疾病列表（按可能性排序）**，每条附：
  - 支持征象（对应到 F2 的具体描述）
  - 相反/不支持证据（避免单向确认偏误）
  - 指南出处（知识库溯源）
  - 置信度分级（高/中/低，或"需结合临床"）
- 表述规范：统一使用"**考虑**/**疑似**/**需结合临床排除**"，严禁"确诊/一定是"

### F4 分级与分期建议

- DR：按 ICDR 国际临床分级给出建议（无明显 DR / 轻度 / 中度 / 重度 NPDR / PDR）+ DME 有无
- AMD：早期 / 中期 / 晚期（地图样萎缩或新生血管性）
- 青光眼：视盘与 RNFL 相关指标描述与随访建议
- 输出附**分级依据条目**

### F5 复查与转诊建议（延伸功能）

- 基于分级结果给出复查间隔建议（3/6/12 个月）
- 识别急症征象（视网膜脱离、玻璃体积血、突发视力下降）→ 建议立即转诊

### F6 医生复核与反馈采集（进化入口）

- 界面提供三种操作：**采纳** / **修正**（选择正确诊断/分级）/ **否决**（附原因）
- 记录：原始影像、模型建议、医生结论、差异类型、时间
- 反馈进入两个通道：① 个案经验（记忆）② 规则/知识修正（知识库）

### F7 可解释与可追溯

- 每条建议 → 征象依据 → 知识库条款，形成三级溯源链
- 支持导出"辅助意见单"（仅供医生参考）

### F8 安全护栏

- 拦截：确诊式断言、用药建议、剂量、安慰性否定（"无需处理"）
- 命中处理：替换为规范话术 + 提示由医生判断

### F9 进化看板（演示亮点）

- 展示：累计反馈数、修正率变化曲线、各疾病准确率/一致性与版本对比

---

### F10 病历与检查报告解析

- 解析 PDF、扫描件和图片中的主诉、现病史、既往史、家族史与诊疗经过。
- 提取视力、眼压、屈光、视野、OCT/OCTA、B 超等眼科检查结果。
- 识别糖尿病、高血压、血脂异常、凝血异常等与眼底病相关的全身背景。
- 保留原始值、单位、参考区间、检查日期和来源位置。
- 对信息缺失、字段冲突或 OCR 低置信度内容单独标记，不擅自补全。

### F11 检验与随访时间轴

- 将 HbA1c、血糖、血压、血脂、肾功能、凝血和炎症指标按时间排列。
- 自动识别新增、改善、稳定、恶化或检查缺失。
- 将全身指标与眼底病灶、OCT 变化和视力变化进行时间对齐。
- 展示用于进展判断的原始证据，避免仅给“进展”二字。

### F12 医生连续问答

- 支持解释、鉴别、缺项、风险、纵向变化、证据来源和反事实问题。
- 每轮回答重新读取当前病例与知识库，不依赖模型记忆补造事实。
- 回答必须区分“病例证据”“医学知识”“模型推断”和“信息缺口”。
- 医生修改病例或结论后，后续回答同步更新上下文。
- 对处方、剂量、手术决定和确定性诊断请求进行拒答。

### F13 证据引用与可追溯

- 每个病灶、疾病假设和分级建议绑定证据节点。
- 医学知识引用到指南名称、版本、条款/页码或 DOI。
- 支持从结论反向定位到影像区域、病历原文和检验数值。
- 知识过期、来源冲突或适用范围不匹配时，必须显示限制。

### F14 多模态冲突提示

- 影像与病历、检验、既往诊断不一致时，不强行统一结论。
- 输出冲突点、可能原因和需要补充的检查。
- 区分数据错误、时间错位、疾病异质性和真实的多病共存。
- 将冲突作为医生复核重点，而不是用模型置信度覆盖。
## 4. 可进化机制设计（本项目的灵魂）

### 4.1 进化闭环

```
   ① 智能体输出辅助意见
            │
            ▼
   ② 医生复核：采纳 / 修正 / 否决（附原因）
            │
   ③ 差异分析：建议 vs 医生结论
            │
   ┌────────┴─────────┐
   ▼                  ▼
④ 记忆沉淀        ⑤ 知识库修正
（个案经验：        （规则完善：
 典型/易错案例）     征象-疾病对应、
                    阈值、边界条件）
   └────────┬─────────┘
            ▼
   ⑥ 评估：与医生金标准对比（准确率/一致性）
            │
            ▼
   ⑦ 版本迭代 v1 → v2（指标提升可量化）
```

### 4.2 三层记忆的用法（针对辅助诊断场景）

| 层级 | 内容 | 作用 |
|---|---|---|
| Tenant 记忆 | 诊断口径、分级标准、表述规范、合规红线 | 统一全院判断标准 |
| User 记忆 | 医生个人偏好与习惯（如更关注黄斑区） | 个体化适配 |
| Agent 记忆 | 被修正的典型案例、易混淆征象、边界情况 | **越用越准** |

### 4.3 进化的三种证据（供评委检验）

1. **行为证据**：同一张片子/同类片子，反馈后再问，结论更接近医生判断
2. **指标证据**：准确率、敏感度、特异度、Kappa 一致性随反馈提升
3. **过程证据**：Agent 记忆条目增长、知识库规则更新记录、版本迭代历史

## 5. 计算机技术方案

### 5.1 总体架构

```
┌── 影像层 ────────────────────────────────┐
│ 眼底影像采集 → 质控 → 预处理 → ROI/视盘定位  │
└──────────────┬───────────────────────────┘
               ▼
┌── 感知层（多模态理解）────────────────────┐
│ 视觉语言模型 VLM：结构化征象提取与描述        │
│ 传统 CV（可选）：血管分割、病灶检测、杯盘比    │
└──────────────┬───────────────────────────┘
               ▼
┌── 知识层（RAG）──────────────────────────┐
│ 指南库 / 征象-疾病映射 / 分级标准 / 判读规范  │
└──────────────┬───────────────────────────┘
               ▼
┌── 推理决策层 ────────────────────────────┐
│ LLM：疑似疾病排序 + 依据生成（强 Schema 约束）│
│ 工具调用：知识检索 / 记忆读写 / 影像分析      │
└──────────────┬───────────────────────────┘
               ▼
┌── 交互与反馈层 ──────────────────────────┐
│ 医生复核界面 → 采纳/修正 → 反馈入库          │
└──────────────┬───────────────────────────┘
               ▼
┌── 进化与治理层 ──────────────────────────┐
│ 记忆沉淀 / 知识修正 / 评估指标 / 版本管理     │
│ 安全护栏 / 日志审计 / 权限控制               │
└──────────────────────────────────────────┘
```

### 5.2 影像质控与预处理

| 环节 | 方法 | 目的 |
|---|---|---|
| 质量评估 | 清晰度（拉普拉斯方差）、曝光直方图、遮挡检测 | 拒绝不可判读图像 |
| 光照校正 | 自适应直方图均衡、Retinex 类方法 | 消除照明不均 |
| ROI 与定位 | 视盘/黄斑检测、血管弓定位 | 病灶定位与区域描述 |
| 血管分割 | U-Net 类分割模型 | 出血/血管异常区分 |
| 病灶检测 | 目标检测/分割（微动脉瘤、出血、渗出） | 提供客观量化指标 |

### 5.3 多模态理解（VLM）

- **作用**：将影像转为结构化、可核对的征象描述，而非直接下诊断
- **提示词约束**：仅描述可见征象；不确定时明确标注"需医生确认"；禁止输出病名结论
- **输出范式**：固定 JSON Schema（区域、征象、程度、置信度、备注）
- **选型建议**：Qwen-VL / InternVL / 商用多模态模型，需用眼底数据实测其征象识别能力

### 5.4 知识增强（RAG）

- 知识库内容：诊疗指南、分级标准、征象-疾病映射、影像判读规范、病历与检验字典、急症规则、鉴别要点和安全话术
- 检索：向量 + 关键词混合召回，返回带出处片段
- 作用：为"疑似疾病排序"提供**可引用依据**，实现可解释

### 5.5 推理与输出约束

- LLM 负责融合（影像征象 + 病历 + 检验 + 随访 + 知识）并生成辅助建议
- **输出强约束**：JSON Schema 固定字段（征象列表、疑似疾病及时序、依据、置信度、免责声明）
- 好处：便于评估、便于审计、便于界面结构化展示

### 5.6 评估与治理

| 维度 | 指标 |
|---|---|
| 征象识别 | 各类征象检出敏感度/特异度 |
| 辅助诊断 | Top-1 / Top-3 命中率、敏感度、特异度、AUC |
| 一致性 | 与医生金标准的 Kappa 系数 |
| 分级一致性 | 分级完全一致率、±1 级一致率 |
| 进化效果 | v1 → v2 指标提升幅度、修正率下降幅度 |
| 安全与问答 | 越界输出拦截率、免责声明覆盖率、引用正确率、拒答正确率 |

### 5.7 技术选型建议

| 环节 | 候选 | 考虑因素 |
|---|---|---|
| 辅助诊断 LLM | DeepSeek / Qwen 系列 | 中文医学语境、成本、可控性 |
| 视觉模型 | Qwen-VL / InternVL / 商用多模态 | 眼底征象识别能力需实测 |
| 向量模型 | BGE-M3 / text-embedding-v3 | 中文医学文本检索 |

## 8. 完整知识库设计

### 8.1 “完整知识库”的定义

这里的“完整”是指在项目承诺的西医眼科范围内形成闭环，而非宣称覆盖全部医学知识：

1. **疾病完整**：每个承诺病种均有定义、危险因素、症状、影像特征、诊断标准、分级、鉴别、急症、随访和局限说明。
2. **维度完整**：影像、病历、眼科检查、实验室检验、既往治疗和随访均有结构化字段。
3. **来源完整**：每条知识可追溯至发布机构、指南版本、年份、条款或 DOI。
4. **术语完整**：中英文名称、缩写、同义词、上下位关系和影像征象定义统一。
5. **更新完整**：具备知识截止日期、过期提醒、冲突裁决、版本对比和回滚流程。
6. **安全完整**：包含急症规则、适用人群、证据不足场景、禁用表述和拒答策略。
7. **评测完整**：覆盖度、召回率、引用正确率和专家一致性均可量化验收。

### 8.2 九类核心知识

| 类别 | 主要内容 | 结构化形式 |
|---|---|---|
| 解剖与生理 | 视网膜、黄斑、视盘、血管、脉络膜、玻璃体和视网膜分层 | 解剖图谱 + 术语树 |
| 疾病知识 | 定义、危险因素、症状、病程、并发症和预后 | 疾病知识卡 |
| 影像判读 | 模态、采集规范、病灶定义、典型与不典型表现 | 征象卡 + 图例 |
| 诊断与分级 | DR/ICDR、DME、AMD、青光眼、RVO 等标准和规则 | 规则表 + 决策树 |
| 鉴别诊断 | 易混疾病、支持/反对征象、关键检查 | 鉴别矩阵 |
| 病历与检验 | 病史字段、眼科检查、实验室指标、参考区间和临床意义 | 字段字典 + 归一化规则 |
| 随访与转诊 | 复查间隔、进展指标、转诊条件和急症路径 | 路径图 + 风险规则 |
| 安全与合规 | 诊断边界、隐私、禁用表述、免责声明和拒答话术 | 规则库 + 话术库 |
| 已审核病例 | 典型案例、边界病例、医生修正原因和随访结果 | 病例记忆 + 检索索引 |

### 8.3 疾病知识卡字段

每张疾病卡至少包含：中文名、英文名、常用编码、同义词、定义、流行病学、危险因素、常见主诉、适用模态、典型征象、诊断标准、分级/分期、必须排除的疾病、关键检查、并发症、急症、随访、证据来源、版本、适用人群、证据局限和常见误诊原因。

### 8.4 影像征象卡字段

每张征象卡至少包含：中英文名称、缩写、定义、解剖区域、常见模态、图像特征、典型疾病、非典型情况、易混征象、严重程度、标注规范、典型图例、反例和知识来源。

### 8.5 征象—疾病—临床证据映射表

| 字段 | 说明 |
|---|---|
| 影像征象组合 | 微动脉瘤、出血、渗出、棉絮斑、水肿、新生血管等 |
| 临床/检验特征 | 糖尿病病程、HbA1c、血压、视力、眼压、既往治疗等 |
| 候选疾病 | 影像与临床证据共同支持的疾病 |
| 支持强度 | 强/中/弱 |
| 支持证据 | 影像、病历、检验或随访依据 |
| 反对证据 | 可降低该疾病可能性的条件 |
| 鉴别疾病 | 最易混淆疾病 |
| 关键区分点 | 用于鉴别的最重要证据 |
| 缺失信息 | 提升置信度所需检查 |
| 来源与版本 | 指南条款、文献 DOI 和生效版本 |

### 8.6 病历与检验字段

| 层级 | 字段示例 |
|---|---|
| 基础信息 | 年龄、性别、家族史、相关全身病 |
| 主诉与病史 | 视力下降、变形、飞蚊、闪光、视野缺损、疼痛、病程、单/双眼 |
| 全身背景 | 糖尿病、高血压、血脂异常、凝血异常、自身免疫病、感染和遗传病 |
| 眼科检查 | BCVA、屈光、眼压、视野、OCT/OCTA、FFA、眼轴、B 超 |
| 检验指标 | HbA1c、血糖、血压、血脂、肾功能、凝血、炎症指标 |
| 纵向信息 | 检查日期、治疗史、术后变化、复发和进展 |

### 8.7 来源优先级与冲突处理

1. 国家卫生健康主管部门、药监部门和国家级诊疗规范；
2. 中华医学会及相关专业学会现行指南/专家共识；
3. AAO、ICO、EURETINA 等国际权威指南；
4. 系统综述、Meta 分析和高质量随机对照研究；
5. 权威教材和经典诊断标准；
6. 高质量观察性研究和真实世界研究；
7. 病例经验只能作为补充，不能单独形成确定性结论。

来源冲突时，系统记录各方观点、适用人群和版本，按上述优先级裁决，并允许医生查看冲突内容。

### 8.8 知识生命周期

```text
资料发现 → 版权检查 → 解析与切分 → 专家审定 → 结构化标注
→ 版本登记 → 检索评测 → 发布 → 使用监控 → 指南更新/纠错
→ 新旧对比 → 审核 → 替换或回滚
```

### 8.9 知识质量指标

| 指标 | 说明 |
|---|---|
| 来源覆盖率 | 每个疾病是否具备定义、诊断、分级、鉴别、急症和随访来源 |
| 引用正确率 | 医学声明是否准确对应原始条款 |
| 时效率 | 现行指南占比、过期知识处置率 |
| 检索召回率 | Top-K 是否召回回答问题所需证据 |
| 专家一致率 | 医学专家对知识条目的独立评分 |
| 冲突解决率 | 知识冲突是否完成裁决并留痕 |
| 拒答正确率 | 超范围、证据不足问题是否被正确识别 |

## 9. 影像与病历全维度分析

### 9.1 输入范围

系统支持 CFP、超广角眼底照相、OCT、OCTA、FFA、B 超及可解析的 PDF/图片报告，同时接入门诊病历、眼科检查、检验和既往随访资料。每种疾病明确必需、条件和可选输入，资料不足时不强行给出确定结论。

### 9.2 标准分析流程

```text
资料接入 → 隐私脱敏 → 影像质控/文档校验
→ 影像分析与病历解析并行
→ 病例级多模态融合 → 候选疾病与分级假设
→ 支持/反对证据与鉴别 → 知识检索与引用核验
→ 安全护栏与不确定性校准 → 结构化报告
→ 医生复核和追问 → 经审核的反馈迭代
```

### 9.3 影像分析

1. 判断图像清晰度、曝光、遮挡、视野、伪影和模态适配性。
2. 分割视盘、黄斑、血管弓和视网膜区域。
3. 检测微动脉瘤、出血、硬性渗出、棉絮斑、玻璃膜疣、水肿、新生血管等病灶。
4. 分析 OCT 视网膜分层、囊样水肿、视网膜内液/下液、RPE 和玻璃膜疣。
5. 输出眼别、象限、黄斑中心距离、面积、数量、密度、对称性和纵向变化。
6. 每个病灶单独给置信度，低置信度内容不直接进入确定性推理。

### 9.4 病历与检验分析

- 提取主诉、病程、症状、危险因素、家族史、眼病史和全身病史。
- 提取既往诊断、治疗、手术、用药和随访信息。
- 统一眼科检查与实验室指标的单位和参考区间。
- 建立时间轴，识别新增、改善、稳定、恶化或资料缺失。
- 识别影像与病历、检验、历史诊断之间的冲突。
- 生成“提高判断所需的信息缺口”，而不是将缺项视为正常。

### 9.5 多模态融合原则

- 影像负责回答“看到了什么”；
- 病历负责回答“发生在谁身上、病程多久、有何危险因素”；
- 检验负责回答“全身状态和可能病因”；
- 随访负责回答“是否进展、复发或治疗相关改变”；
- 规则与知识负责回答“这些证据是否符合疾病标准”；
- 模型负责识别、融合和排序，不负责创造医学规则。

冲突处理规则：不强行统一、不隐藏反证、不用一个高分结果覆盖矛盾信息。系统列出冲突点，并提示医生复核原始资料或补充检查。

### 9.6 候选疾病与分级输出

每个候选疾病必须包含：可能性等级和概率区间、支持证据、反对证据、需鉴别疾病、关键区分点、当前分级/分期、影响排序的因素、缺失信息和置信度。概率只用于表达模型不确定性，不能表述为临床确诊概率。

### 9.7 结构化报告字段

| 字段 | 内容 |
|---|---|
| 病例摘要 | 年龄、主诉、危险因素、病程和既往诊疗 |
| 影像质控 | 是否可判读、问题类型、是否建议重拍 |
| 影像所见 | 眼别、区域、病灶、范围、数量和置信度 |
| 结构量化 | 视盘、杯盘比、黄斑、视网膜厚度、病灶面积 |
| 病历/检验 | 关键阳性、阴性和缺失信息 |
| 疾病排序 | Top-N 候选、置信度和支持/反对证据 |
| 分级建议 | 对应标准、级别和判断条件 |
| 鉴别诊断 | 易混疾病与区分点 |
| 风险提示 | 急症、双眼受累、快速进展或高危征象 |
| 下一步诊断路径 | 复核、补充检查、转诊或随访，不含治疗处方 |
| 证据引用 | 指南名称、版本、条款和链接 |
| 限制声明 | 适用范围、信息缺口、不确定性和医生复核要求 |

### 10.1 支持的问法

| 类型 | 示例 |
|---|---|
| 解释型 | “为什么把糖尿病黄斑水肿排在第一位？” |

| 纵向型 | “和半年前相比有哪些进展？” |
| 反事实型 | “如果没有硬性渗出，排序会怎样变化？” |
| 证据型 | “这条结论依据哪版指南？” |
| 边界型 | “现在能确定为几级吗？” |
| 越界型 | “直接给我一套药物和剂量。” |

### 10.2 回答约束

1. **病例优先**：先检索当前病例资料，再检索通用知识。
2. **证据最小充分**：回答只使用支持结论所需证据，并同时列出反证。
3. **不编造**：资料未提供时明确说“当前病例未提供”。
4. **逐项可溯源**：关键事实绑定影像区域、病历字段、检验值或知识条款。
5. **不确定就说明**：给出高/中/低置信度和影响因素。
6. **接口一致**：回答默认采用“结论—病例依据—医学依据—反向考虑—信息缺口—复核提示”。
7. **拒绝越界**：不提供处方、剂量、疗程、手术决定或最终诊断。

### 10.3 示例：鉴别诊断

**医生**：有没有可能是视网膜静脉阻塞？

**智能体**：

- 支持 RVO：出血沿血管分布、静脉扩张迂曲、单眼突然发病等。
- 反对 RVO：双眼对称微血管瘤、病程缓慢、糖尿病背景更符合 DR。
- 无法仅凭影像排除：少数病例可同时存在 DR 与 RVO。
- 建议补充：确认起病方式、单/双眼、血压和凝血情况，结合超广角或 FFA 判断缺血范围。
- 结论：当前证据更支持 DR，但不能完全排除合并 RVO，需医生结合病程和检查判断。

### 10.4 示例：越界请求

**医生**：直接给我一套抗 VEGF 用药和剂量。

**智能体**：

> 我不能提供具体用药、剂量或治疗方案。本系统只辅助影像判读、鉴别诊断和诊断路径梳理。是否治疗及具体方案应由具备资质的眼科医师结合面诊、OCT/FFA、既往治疗和全身情况决定。我可以继续整理支持治疗评估的影像与检查证据。

### 10.5 问答评测

问答能力不能只用“回答像不像医生”评价，应采用固定测试集检查事实正确率、病例证据一致率、引用正确率、拒答正确率、越界拦截率和多轮一致性，并由眼科医生进行盲评。

## 13. 交付物与验收标准

**交付物**

1. 可运行智能体（本地部署，医生复核界面 + 反馈采集）
2. 开发设计文档（按赛事模板）

**验收标准**

| 项 | 标准 |
|---|---|
| 输入 | 支持眼底影像、OCT、PDF/图片病历、眼科检查和检验资料 |
| 影像质控 | 能识别不可判读图像并给出原因和重拍建议 |
| 病灶分析 | 能输出病灶类型、眼别、区域、范围、置信度和可视化 |

| 医生问答 | 能回答解释、鉴别、缺项、纵向变化和证据来源，并正确拒答越界问题 |
| 知识库 | P0 疾病具备诊断、分级、鉴别、急症、随访和安全知识 |
| 输出 | 结构化影像所见 + 疑似疾病排序 + 分级 + 支持/反对证据 + 风险提示 |
| 可解释 | 每条建议可溯源到病例证据和知识库条款、版本 |
| 安全 | 测试集内越界表述拦截率 100%，急症召回满足预设门槛 |
| 进化 | 能展示同类病例在受控反馈后排序或解释质量改善 |
| 演示 | 全流程 ≤5 分钟可现场演示 |
