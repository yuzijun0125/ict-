# ICT 大赛项目 · 中西医结合眼底病智能诊疗方案推荐智能体

第十一届华为 ICT 大赛创新赛 **赛题3**参赛项目仓库。

> **赛题**：基于华为 ModelEngine / Nexent，打造可进化决策智能体
> **研究方向**：眼科 · 眼底影像 × **中西医结合**
> **核心输入**：眼底影像 + 西医临床信息 + 中医四诊信息
> **核心输出**：西医分级建议 + 中医证型建议 + **中西医结合方案建议**

---

## 项目一句话

**把"眼底片子"和"中医辨证"打通的 AI 助手。**

> 让眼底影像能被中医读懂，让中医辨证能被眼科医生用上，最终给出**可解释、可追溯、可进化**的中西医结合方案建议——**最终拍板的一定是医生**。

---

## 要解决的痛点

| 痛点 | 表现 |
|---|---|
| ① 语言不通 | 西医说"出血/渗出/ICDR 分级"，中医说"气阴两虚/血瘀阻络"，**两套体系没有标准对应关系** |
| ② 人分两科 | 眼科医生不懂辨证，中医师看不懂眼底影像 |
| ③ 结合靠经验 | "眼底出血多→该用活血化瘀"只存在于老医生脑中，**没有结构化载体** |
| ④ 方案各自为政 | 西医方案与中医方案**谁先谁后、如何协同，缺统一依据** |
| ⑤ 疗效尺子不同 | 西医看 BCVA/CMT，中医看证候积分 |
| ⑥ 证据等级不同 | RCT 证据与辨证论治经验**难以合并推荐** |

> **核心矛盾**：中西医各自的诊疗逻辑都很完整，但**缺少一个能在两者之间"翻译"和"协调"的中间层**。

---

## 核心创新：三张映射表 ★

这是本项目最硬的原创贡献，也是"中西医结合中间层"的技术实现。

| 映射表 | 作用 |
|---|---|
| ① 影像征象 ↔ 疾病分级 | 西医侧推理（如"4 象限出血+静脉串珠"→ 重度 NPDR） |
| ② 四诊信息 ↔ 中医证型 | 中医侧推理（如"口干乏力+舌暗红少苔+脉细涩"→ 气阴两虚兼血瘀） |
| ③ **征象 ↔ 证型 ↔ 方案** ★ | **中西医结合推理**（把经验变成可推理、可修正的结构化知识） |

---

## 系统流程

```
患者眼底影像 + 四诊信息
        │
        ├─► ① 影像质控（不清楚→建议重拍）
        ├─► ② 西医分析（征象描述 → 疾病分级建议）
        ├─► ③ 中医分析（四诊结构化 → 证型建议）
        ├─► ④ 映射引擎 ★（征象 ↔ 证型 建立关联）
        ├─► ⑤ 方案生成（中西医结合策略 + 排序 + 依据）
        └─► ⑥ 安全护栏（拦截处方/剂量/绝对化表述）
                        │
                        ▼
                医生复核：采纳 / 修改 / 否决
                        │
                        ▼
        反馈入库 → 映射关系修正 → 版本迭代（可进化）
```

---

## "可进化"的独特设计

**三类医生共同反馈**——这是"中西医结合"真正落到实处的技术体现：

| 反馈来源 | 修正什么 |
|---|---|
| 西医医生 | 西医分级、转诊判断 |
| 中医师 | 证型辨识、治法方向 |
| 中西医结合医生 | **映射关系本身** |

**进化的三类证据**：行为证据（反馈后方案更接近医生判断）、数据证据（准确率/采纳率/Kappa 提升）、过程证据（映射表增长、规则修正、版本历史）。

---

## 三条不能破的底线

1. **只给方案思路，不给处方剂量**（不输出方剂组成、剂量、用法）
2. **必须标注依据来源与证据等级**（中医内容要说明是循证还是经验性）
3. **医生必须在环**（中医师与西医共同确认）

> ⚠️ **合规声明**：本项目定位为**科研与竞赛演示用辅助决策工具**，非医疗器械，不用于临床独立诊疗决策，未经 NMPA 注册不得用于临床。
